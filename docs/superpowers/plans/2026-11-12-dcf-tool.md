# DCF Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Python web app where a retail investor enters a ticker and gets a fair-value range, sensitivity, reverse DCF, WACC explainer and peer comparison, in the asset's own currency.

**Architecture:** All finance logic lives in a pure, unit-tested Python package (`dcf`). A FastAPI app exposes two JSON endpoints (`/api/analyze`, `/api/model`) and serves a no-build vanilla-JS page that only renders results and formats currency; it contains no model math. Data providers sit behind one interface so a fake provider drives tests and the browser tests.

**Tech Stack:** Python 3.12, FastAPI + uvicorn, yfinance, requests, SQLite (stdlib), pytest, httpx (API tests), Playwright for Python (browser tests). Frontend: plain HTML/CSS/ES modules, `Intl.NumberFormat` for currency.

**Spec:** `docs/superpowers/specs/2026-11-12-dcf-tool-design.md` (read it first; section numbers below refer to it). Visual source of truth: `docs/mockups/dcf-results-page-mockup.html`.

## Global Constraints

- Language Python; web page UI; free data sources only; no accounts or user database (spec 11).
- Money is shown in the **trading currency** of the asset with the correct symbol; never hard-code "$" (spec 7). All money values in API payloads are absolute amounts in the trading currency; the frontend formats them with `Intl.NumberFormat`.
- The page shows a fair value **range** (bear/base/bull), never a single number (spec 3, 5).
- Every results page carries an "educational estimate, not financial advice" line (spec 11).
- Rates and percentages inside Python are **percent points** (8.6 means 8.6%), matching the mockup.
- Model rules (spec 8): growth starts at the user's rate and fades half-way toward long-term growth over the horizon, `g_i = g + (t - g) * ((i - 1) / n) * 0.5`; terminal value is perpetuity growth from the final year; discount rate must exceed long-term growth; stock-based pay (SBC) is on by default.
- Scenario spreads: bear = growth -4, margin -3, discount rate +1, long-term growth -0.5 (not below 0); bull = growth +4, margin +3, discount rate -0.5 (but at least long-term growth + 2), long-term growth unchanged. Sensitivity flex: discount rate +/-1, growth +/-3, margin +/-3, long-term growth +/-1. Horizons: 3, 5, 10 (default 5).
- Defaults: equity risk premium 4.5, long-term growth 2.5, tax rate 21, pre-tax cost of debt 5.0 (all labelled as assumptions in the UI).
- Detection rules (spec 9): bank/insurer by industry; loss-making = latest-year FCF <= 0 or FCF negative in 2+ of the last 4 years; at least 2 annual statement years needed; annual figures only.
- Cache provider data about 24 hours (spec 10). Free-tier limits are unverified; confirm them in Task 8 and Task 10 before relying on them.
- Accessibility (spec 11): meaning never by colour alone; tooltips work on hover, keyboard focus and tap; respect `prefers-reduced-motion`; light and dark mode.

## Review Focus

Inputs the spec implies but its sections do not spell out, most likely to bite first. Each has a test in the task named in brackets.

1. **Odd ticker input** (lowercase, spaces, `BRK.B`, `BRK-B`, empty, punctuation or script-like text): normalise, never crash, never reach the provider with garbage. [Task 11]
2. **Extreme or missing company data** (growth 60%, margin 70%, shrinking revenue, no beta, no SBC row, no tax or interest data, zero or missing shares): suggestions are clamped with a visible note, defaults fill gaps with a "partial data" banner, no NaN, no negative per-share value, no 500. [Tasks 1, 4, 11, 12]
3. **Provider outage or rate limit**: stale cache is served with a "data may be old" banner; with no cache the user gets a designed error state, not a stack trace. [Tasks 7, 8, 12, 16]
4. **Out-of-order slider responses and invalid combinations** (discount rate not above long-term growth): UI shows only the newest response; API returns 422 and UI limits prevent the combination. [Tasks 12, 14]
5. **Quotation units and currency mismatch** (London pence, ADR reporting in a different currency than it trades): prices normalised before maths; statements converted at spot FX with a visible note; no rate means a blocking state, not a wrong number. [Tasks 5, 8, 11, 16]
